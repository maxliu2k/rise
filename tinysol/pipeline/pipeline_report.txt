*** BOTH DATASETS ARE NOW 12-CLASS AND SHARE ONE LABEL SPACE (config.CANONICAL_LABELS). ***
Philharmonia moved from 9 to 12 classes when prep_data.py began fetching oboe / double-bass /
french-horn from the Internet Archive mirror. TinySOL already had all 12, so the two datasets are
now index-compatible and cross-dataset evaluation needs no label remapping.

Run TinySOL with:  RISE_DATA_ROOT=$RISE_TINYSOL_ROOT
(no RISE_TARGET_LABELS needed — the canonical 12 are the default)

12 classes, ALPHABETICAL (this order fixes the label indices; reordering invalidates checkpoints):
  bassoon, cello, clarinet, double-bass, flute, french-horn,
  oboe, trombone, trumpet, tuba, viola, violin
  strings   : violin, viola, cello, double-bass
  woodwinds : flute, clarinet, oboe, bassoon
  brass     : trumpet, french-horn, trombone, tuba
Note the HYPHENS in double-bass / french-horn: they match the Philharmonia archive's filename
field. TinySOL folder names map onto these in build_tinysol_manifest.py.

*** CHECKPOINTS BELOW ARE INVALID — RETRAIN REQUIRED ***
The PANNs results in this report were produced BEFORE the label set was unified. They used a
family-grouped 12-label order (violin, viola, cello, double bass, ...); the canonical order is now
ALPHABETICAL, so every saved label->index mapping has shifted. panns_probe.pt / panns_finetune.pt
predict under the old indices and must be retrained before their numbers are quoted again. The
artifacts here (windows.csv, splits.csv, manifest_labeled.csv) have been relabeled to the
canonical names and remain valid — only the model checkpoints are stale.

================================================================
NOISE SWEEP (test split only, inference only — no retraining)
================================================================
Noise source : ESC-50 (2000 environmental clips) for "real"; numpy Gaussian for "white".
               Stored OUTSIDE git at ~/Downloads/noise_sources (override: RISE_NOISE_ROOT).
               Noise resampled to 22050 Hz; random 3 s segment per window.
SNR levels   : clean, 20, 10, 0, -5 dB  x  {white, real}  = 9 conditions
               (clean is SHARED, not duplicated — it points at work/windows/).
SNR math     : P = mean(x^2); alpha = sqrt(P_sig / (P_noise * 10^(SNR/10))); x + alpha*noise.
               NO re-normalization after mixing. Written float32 WAV (peaks reach 9.2 at
               real/-5 dB — 16-bit PCM would have clipped and corrupted the low-SNR conditions).
Seed scheme  : sha256("{window_id}|{noise_type}|{snr}")[:4] -> same window always gets the same
               noise realization; reproducible across reruns and IDENTICAL for every model, so
               predictions stay paired for McNemar / bootstrap.
Generated ONCE, shared: work/windows_noisy/{noise_type}/snr{level}/<window_id>.wav
               5784 files, 1.4 GB (git-ignored).
VALIDATION (B5): measured-vs-target SNR error = 0.000000 dB across all 8 noisy conditions on 5
               sampled windows (spec: <0.1 dB). P_signal asserted ~= TARGET_RMS^2 per window.
               Listenable 0 dB samples in work/windows_noisy/_validation_samples/.

a barely-audible amount of noise. Clean-trained models are NOT robust; this motivates the
noise-augmented training condition (separate experiment, not run here).
